# 岗位任务控制、候选人边界与简历归档改版设计

- 日期：2026-09-23
- 状态：设计已确认，待实施计划复核
- 本轮验收边界：LLM API 与 BOSS 真站最终联调暂缓，开发和自动验收使用确定性模拟；除此之外，工作台、岗位管理、简历库和候选人库按本规格完整交付。
- 基线规格：

  - [BOSS 直聘本机全自动筛选与共享简历库](./2026-09-16-boss-resume-screening-design.md)

## 1. 改版目标

本次改版解决以下已确认问题：

1. 工作台不是岗位视角，刷新后无法恢复任务，启动、暂停、继续、终止尚未形成真实 Agent 控制闭环。
2. Agent 浏览到 BOSS 人员后就创建候选人，导致候选人库包含未联系、低分、跳过和联系失败人员。
3. Agent 已有附件下载与上传方法，但尚未接入实际执行主链路。
4. 简历只能通过候选人间接关联岗位，无法直接表达 HR 手工导入的岗位 PDF。
5. 简历库上传入口依赖已有候选人且只支持单文件，不符合 HR 按岗位批量归档 PDF 的使用方式。
6. 页面长期展示“暂未接入”“不会伪造运行结果”等占位内容，无法作为可用工作台。

改版后的核心原则：

- 工作台以岗位为入口，任务控制必须对应真实服务端状态和真实 Agent 行为。
- BOSS 筛选对象与正式候选人分离；只有 Agent 确认联系成功后才创建候选人。
- 候选人联系成功后即进入“等待简历”，不要求当场收到附件。
- Agent 常驻并持续收取当前 HR 所有等待简历人员的 PDF。
- HR 手工导入的 PDF 只按岗位归档，不解析、不评分、不创建候选人。
- 自动化不得绕过验证码，不得在暂停或终止生效后继续发起新联系。

## 2. 产品信息架构

### 2.1 01 工作台

工作台主页按岗位展示卡片。每张岗位卡展示：

- 岗位名称和启用状态；
- 配置完整度；
- 当前活动任务状态；
- 已处理人数与目标人数；
- 已联系、等待简历、已收到简历、待复核和失败数量；
- 当前执行 Agent 的机器名称与在线状态；
- 根据状态提供“启动任务”“暂停任务”“继续任务”“终止任务”；
- 点击岗位卡片进入“02 岗位管理”的对应岗位详情。

工作台不重复编辑岗位配置，只负责总览和运行控制。

### 2.2 02 岗位管理

岗位详情统一维护：

- 岗位名称与 JD；
- BOSS 岗位页面地址；
- 默认筛选人数；
- 评分阈值；
- 关键资料清单；
- 招呼模板；
- 每小时联系上限；
- 最小和最大操作间隔；
- 启用或停用状态；
- 当前任务及历史筛选记录。

配置不完整时，工作台岗位卡显示“完善配置”并禁止启动。点击后直接进入该岗位详情并标出缺失项。

### 2.3 03 简历库

简历库按岗位分类展示 PDF，支持两个来源：

- Agent 联系成功后收到的附件；
- HR 手工批量导入的 PDF。

简历库提供“选择岗位 → 批量选择 PDF → 导入”的入口。手工导入项直接显示原 PDF 文件名。

### 2.4 04 候选人库

候选人库只展示 Agent 已确认联系成功的人：

- `waiting_resume`：已联系成功，等待简历；
- `resume_received`：已收到并完成岗位归档；
- `pending_job_assignment`：收到简历，但存在多个待收岗位，等待 HR 选择归档岗位。

低分、跳过、待复核、未联系和联系失败人员只保留在任务历史中，不进入候选人库。

## 3. 岗位任务规则

### 3.1 每岗位唯一活动任务

同一岗位在全系统最多有一个活动任务。活动状态包括：

- `ready`：已经创建并分配 Agent，等待 Agent 接收；
- `running`：Agent 正在执行；
- `pausing`：已请求安全暂停，正在收口当前候选人；
- `paused`：已暂停，可继续；
- `cancelling`：已请求安全终止，正在收口当前候选人。

终态包括：

- `completed`；
- `cancelled`；
- `failed`。

只有任务进入终态后，该岗位才能启动下一轮任务。服务端必须使用事务与数据库约束或等价锁机制防止并发创建两个活动任务。

### 3.2 启动任务

启动条件：

- 岗位已启用；
- 岗位默认配置完整；
- 该岗位没有活动任务；
- HR 选择了一台在线且空闲的 Agent；
- Agent 属于当前 HR，管理员按既有全局权限处理；
- Agent 的 BOSS 登录状态可用。

岗位默认配置直接用于任务，不在每次启动时重复编辑。任务保存启动时的完整快照，岗位后续修改不影响运行中任务。

点击“启动任务”后：

1. 服务端原子创建 `ready` 任务并指定目标 Agent；
2. 只有目标 Agent 可以领取该任务；
3. Agent 接收后任务变为 `running`；
4. Agent 自动打开岗位保存的 BOSS 页面地址；
5. 地址失效、登录失效或页面岗位不一致时，任务安全暂停并在工作台显示具体原因；
6. HR 修复后点击“继续任务”，Agent 从断点恢复。

### 3.3 安全暂停

点击“暂停任务”后，任务先进入 `pausing`：

- 已开始处理的当前候选人完成必要的结果确认；
- 如果尚未执行真实发送动作，则不得再发送；
- 当前候选人收口后进入 `paused`；
- Agent 保持在线，不筛选或联系新人；
- 等待简历监视不受暂停影响。

### 3.4 安全终止

原“停止任务”统一改名为“终止任务”。点击后任务进入 `cancelling`：

- 与暂停相同，安全收口当前候选人；
- 尚未发送时不得再发送；
- 收口后进入不可恢复的 `cancelled`；
- 已处理的筛选、评分、联系和审计记录全部保留；
- Agent 释放为“空闲”；
- 等待简历监视继续运行。

### 3.5 控制屏障

Agent 必须定期读取任务状态，并在以下动作前再次检查控制状态：

- 开始处理下一位筛选对象；
- 调用评分服务；
- 预留联系事件；
- 在 BOSS 页面执行真实发送；
- 开始下一页处理。

服务端在联系预留时必须校验：

- 任务为 `running`；
- 请求来自任务指定 Agent；
- 请求用户有任务权限；
- 岗位、任务和筛选记录一致。

这样即使 Agent 状态轮询延迟，服务端仍能阻断暂停或终止后的新联系。

## 4. Agent 常驻与设备状态

### 4.1 常驻模式

Agent 登录后作为本机后台程序常驻，循环执行：

1. 上报心跳、登录状态、空闲/繁忙状态、当前任务和岗位；
2. 接收明确分配给本机的任务；
3. 执行任务并定期同步控制状态；
4. 持续监视当前 HR 的全部待收简历人员；
5. 暂停时停止新筛选，但继续收取附件；
6. 终止或完成后释放任务，回到空闲状态；
7. 重启后恢复未结束任务，并恢复待收简历监视。

一台 Agent 同时最多执行一个筛选任务，但附件监视属于后台职责，不占用筛选任务名额。

### 4.2 岗位导航

Agent 使用岗位保存的 `boss_entry_url` 自动进入对应页面。执行前必须校验：

- 页面可访问；
- 登录态有效；
- 页面与任务岗位相符；
- 未出现验证码或风控页。

校验失败时不得继续操作，任务进入安全暂停并记录原因。不得自动绕过验证码。

## 5. 筛选记录与候选人边界

### 5.1 筛选记录

Agent 浏览到的人先写入任务下的筛选记录，不创建 Candidate。筛选记录保存：

- BOSS 稳定 ID或弱指纹；
- 页面显示姓名和摘要；
- 当前岗位、任务与位置序号；
- 硬筛、评分和关键资料结果；
- 跳过、待复核、失败或联系结果；
- 审计时间和必要证据。

筛选记录用于断点恢复、全局联系去重、任务统计和审计。

### 5.2 创建候选人的唯一时点

只有 BOSS 页面已明确验证消息发送成功，且服务端联系事件确认为成功后，才将对应筛选对象提升为 Candidate。

创建或复用规则：

- 优先使用 BOSS 稳定 ID；
- 联系成功后写入 Candidate、CandidateJob 和候选人状态；
- 初始状态为 `waiting_resume`；
- 发送失败、结果未知、低分、跳过和待复核均不创建 Candidate；
- 已联系成功但暂未收到 PDF 的人立即进入候选人库。

候选人创建与联系确认必须保持幂等，重试不能生成重复 Candidate。

## 6. Agent 附件收取与岗位归档

### 6.1 持续监视

Agent 给不同候选人发送消息时不阻塞等待单个人的附件。任务运行期间以及后续常驻期间，Agent持续监视当前 HR 所有 `waiting_resume` 人员的 BOSS 会话。

任务暂停、完成或终止后，附件监视仍继续。Agent 重启后从服务端恢复待收名单。

### 6.2 收到附件

收到 PDF 后：

1. 下载到本机受保护的临时目录；
2. 计算文件哈希；
3. 上传云端；
4. 上传成功后清理可安全删除的本地临时副本；
5. 记录附件来源、联系事件、候选人和岗位归档关系；
6. 不自动评分、不自动发起新的联系。

### 6.3 多岗位冲突

- 候选人只有一个等待简历岗位：自动归档到该岗位；
- 候选人对应多个等待简历岗位：简历进入 `pending_job_assignment`，由 HR 选择一个岗位；
- 确认前不得把同一附件自动复制到多个岗位；
- HR 选定后候选人更新为 `resume_received`。

## 7. HR 手工批量导入

### 7.1 交互

入口位于“03 简历库”：

1. HR 选择一个岗位；
2. 批量选择一个或多个 PDF；
3. 系统逐文件上传并展示进度；
4. 结果区分别显示成功、重复跳过和失败。

### 7.2 业务规则

手工导入 PDF：

- 仅保存原文件及最小元数据；
- 不解析正文；
- 不调用 LLM；
- 不评分；
- 不创建 Candidate；
- 不提供“转为候选人”功能；
- 不触发联系；
- 使用原文件名展示；
- 同一岗位内按文件内容哈希去重；
- 相同 PDF 可以分别归档到不同岗位。

批量导入按文件独立提交，单个文件失败不回滚其他成功文件。重试必须保持幂等。

## 8. 数据模型调整

### 8.1 ScreeningRecord

新增或从现有任务项演进的筛选记录，用于保存尚未成为 Candidate 的 BOSS 人员。它必须能在联系成功后与 Candidate 建立可追溯关联。

建议字段：

- `task_id`
- `job_id`
- `boss_id`
- `fingerprint`
- `display_name`
- `source_payload_json`
- `status`
- `score_snapshot_json`
- `candidate_id`（联系成功后可空转非空）
- `outreach_event_id`
- `position_index`
- 时间字段

### 8.2 Resume

Resume 不再强制属于 Candidate，保留可空 `candidate_id`，并增加或配合归档关系表达：

- 原始文件名；
- 文件哈希；
- 来源：`boss_attachment` 或 `manual_upload`；
- 上传人；
- 解析状态；手工导入固定为“不解析”；
- 附件联系事件；
- 多岗位待确认状态。

### 8.3 ResumeJobArchive

新增简历岗位归档关系：

- `resume_id`
- `job_id`
- `source`
- `assigned_by_user_id`
- `assigned_at`

唯一约束为 `(resume_id, job_id)`。手工导入的去重规则使用 `(job_id, file_hash)`。

### 8.4 JobPosting

岗位增加或持久化以下默认配置：

- `default_requested_count`
- `critical_fields_json`
- `critical_fields_confirmed_at`
- 现有评分阈值、招呼模板、BOSS 地址和限速字段继续使用。

只有配置完整且启用的岗位可启动任务。

### 8.5 ScreeningTask 与 AgentRun

任务增加明确的 Agent 分配和安全控制信息：

- `assigned_agent_run_id` 或稳定 Agent 标识；
- `control_requested_at`
- `pause_reason`
- 活动任务唯一性保障。

Agent 心跳增加：

- `current_task_id`
- `current_job_id`
- `availability`：`idle | busy | paused | offline | error`
- BOSS 登录状态和最近错误。

## 9. API 设计

### 9.1 岗位和任务

至少提供：

- 按岗位查询当前活动任务及历史任务；
- 查询工作台岗位卡聚合状态；
- 为岗位选择 Agent 并启动任务；
- 请求安全暂停；
- 继续任务；
- 请求安全终止；
- Agent 拉取仅分配给自己的任务；
- Agent 查询当前任务控制状态；
- Agent 确认暂停、终止和完成。

所有写操作必须保持既有 owner/admin 权限边界，并为状态转换使用事务锁。

### 9.2 候选人与附件

至少提供：

- 联系确认后幂等提升筛选记录为 Candidate；
- 查询当前 HR 的全部待收简历人员；
- 上传 Agent 收到的 PDF 并关联联系事件；
- 查询和处理多岗位待确认归档；
- 候选人库默认只返回联系成功的 Candidate。

### 9.3 手工导入

至少提供：

- 指定 `job_id` 的多 PDF 上传；
- 文件类型和大小校验；
- 同岗位文件哈希去重；
- 逐文件返回 `imported | duplicate | failed`；
- 按岗位查询归档简历。

## 10. Web 交互与空状态

### 10.1 工作台

- 页面加载即查询岗位及真实任务状态；
- 每个活动任务定期刷新，页面刷新后可恢复；
- Agent 离线、岗位配置不完整和任务状态冲突均显示明确原因；
- 控制按钮提交后先显示请求中状态，服务端确认后再更新；
- 不显示伪造统计或演示活动。

### 10.2 占位文案处理

移除生产页面中的常驻“暂未接入”“不会伪造运行结果”等开发说明：

- 无数据：显示正常空状态和下一步操作；
- 接口失败：显示错误原因和重试按钮；
- 功能无数据来源：本轮实现真实接口，不能用静态数字替代。

### 10.3 简历库

- 顶部提供岗位选择与批量 PDF 导入；
- 左侧或标签按岗位切换；
- 简历行显示原文件名、来源、导入时间、候选人（如有）和归档状态；
- 多岗位待确认提供明确操作入口；
- 导入结束展示逐文件结果，不因局部失败丢失成功结果。

## 11. 权限与数据范围

- 普通 HR 只能控制自己创建并分配给自己 Agent 的任务；
- 普通 HR 的 Agent 只监视该 HR 已联系的待收简历人员；
- admin 保留全局查看和管理能力；
- 岗位仍属于团队共享数据，不新增公司级多租户；
- 简历原件和候选人隐私只通过鉴权 API 访问；
- Agent 的 BOSS Profile、临时下载和截图目录不得上传或进入 Git。

## 12. 历史数据迁移

历史数据不得直接删除。迁移规则：

1. 有明确成功联系事件的 Candidate 保留为候选人；
2. 已有 Resume 根据可确认的 CandidateJob 或联系岗位建立归档关系；
3. 没有成功联系证据的 Candidate 转为或映射到历史筛选记录；
4. 无法判断联系状态或岗位归属的记录进入人工核对；
5. 原评分、联系、任务、简历和审计外键保持可追溯；
6. 迁移支持重复执行；
7. SQLite 和 PostgreSQL 分别验证；生产迁移前必须备份。

若现有外键导致无法无损移除 Candidate，首阶段允许保留底层历史 Candidate 行，但候选人查询必须通过明确的“已确认联系”条件过滤；后续再执行物理模型收敛。不得仅在前端隐藏来代替服务端语义约束。

## 13. 异常与安全

- API 不可达：Agent 停止新联系，保留本地最小恢复状态；
- BOSS 登录失效、验证码、风控或页面结构异常：安全暂停并通知 HR；
- 发送结果未知：不得创建正式候选人，记录待人工核验；
- 附件下载失败：候选人保持“等待简历”，允许后续重试；
- 上传成功但响应丢失：以哈希和联系事件幂等恢复；
- 暂停或终止请求后，服务端禁止新的联系预留；
- 手工导入只接受 PDF，限制单文件大小、批次数量和安全文件名；
- 所有状态变更写审计日志。

## 14. 测试与验收

### 14.1 自动测试

- 每岗位唯一活动任务的并发测试；
- 只允许指定在线空闲 Agent 领取；
- Agent 心跳、重启恢复和任务状态同步；
- 暂停、继续、终止状态机与发送前服务端屏障；
- 页面刷新后恢复岗位任务；
- 联系成功前不创建候选人；
- 发送失败或结果未知不进入候选人库；
- 联系成功后创建候选人并标记等待简历；
- 单岗位附件自动归档；
- 多岗位附件进入待确认并由 HR 选择；
- HR 多 PDF 导入、不解析、不创建候选人；
- 同岗位重复文件跳过、跨岗位允许归档；
- 历史数据迁移幂等与外键完整性；
- Web 岗位卡控制、空状态、错误和批量导入结果测试。

### 14.2 人工验收

- 为不同岗位保存完整配置；
- 工作台显示不同岗位卡并可选择指定在线 Agent 启动；
- Agent 自动打开正确 BOSS 页面；
- 暂停和终止在当前候选人安全收口后生效；
- Agent 联系成功后候选人显示“等待简历”；
- 任务结束后 Agent 仍能收到并上传后续 PDF；
- 同候选人多岗位时出现待确认分岗；
- 简历库可选择岗位批量导入 PDF，重复文件被跳过；
- 手工 PDF 不出现在候选人库；
- 页面不再显示开发阶段的常驻占位文案。

### 14.3 模拟集成与本轮完成标准

本轮不以真实 LLM 密钥或 BOSS 真站账号作为完成前提。所有外部能力通过与正式接口相同的数据结构进行确定性模拟：

- LLM 关键资料建议、评分和结构化输出由固定测试替身返回，可稳定覆盖成功、格式错误和服务异常；
- BOSS 页面导航、登录、候选人读取、招呼发送和附件到达由现有假页面、假 Agent 与 API 测试替身模拟；
- 模拟仅存在于测试或明确的开发适配层，不在生产页面展示“模拟结果”，不写入真实密钥；
- 业务层和页面只依赖现有接口契约。后续接入真实 LLM 时只替换外部适配实现与配置，不修改岗位、任务、简历或候选人数据流；
- 自动验收必须跑通：岗位配置 → 工作台启动与控制 → 联系成功后形成候选人 → 等待/收到简历 → 自动或人工分岗 → 简历归档；
- 工作台、岗位管理、简历库和候选人库的非外部依赖功能，以及生产占位文案清理，全部属于本轮交付，不能以“等待真实 LLM”延期。

本轮完成必须同时满足：后端全量测试通过、前端全量测试通过、生产构建通过、四个页面目标交互均有自动测试、代码中无测试密钥和生产模拟数据。真实 LLM 与 BOSS 真站只作为后续人工联调项，不影响本轮“模拟链路完成”的判定。

## 15. 兼容与覆盖声明

本规格覆盖旧规格中的以下规则：

- “浏览到人员即创建 Candidate”改为“先建立筛选记录，联系确认成功后再创建 Candidate”；
- “Resume 必须依附 Candidate”改为“手工岗位归档可无 Candidate”；
- “简历通过 CandidateJob 间接按岗位查询”改为“使用直接岗位归档关系”；
- “Web 创建 ready、任意 Agent 领取”改为“岗位视角选择指定在线 Agent 启动”；
- “单个当前会话任务”改为“按岗位恢复活动任务和历史”；
- “任务终止”采用安全收口，不等于立即中断当前浏览器动作；
- “任务结束即停止 Agent”改为“Agent 常驻并持续收取等待简历”。

未被本规格覆盖的鉴权、部署、限速、全局联系去重、审计和合规规则继续有效。
