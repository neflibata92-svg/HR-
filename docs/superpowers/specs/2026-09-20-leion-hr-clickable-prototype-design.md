# LEION HR 可点击管理后台原型设计

## 目标

在现有 BeyondX 风格工作台视觉稿基础上，制作一套可点击切换的五页面管理后台原型，供产品确认和后续正式前端开发参考。

## 用户与核心规则

- 使用者：招聘团队中的 HR。
- 品牌名称统一为 `LEION HR`。
- 每位 HR 每个自然日共有 200 次打招呼额度。
- 200 次额度由该 HR 当天运行的所有岗位共同消耗，不给单个岗位分配独立额度。
- 简历库必须先按岗位筛选，再展示属于该岗位的简历。
- 同一候选人可以匹配多个岗位，但底层仍视为同一位候选人，避免重复保存简历。

## 原型范围

原型沿用现有单个 HTML 文件，以轻量 JavaScript 实现页面切换和演示交互，不连接真实后端，不改变正式产品代码。

### 1. 工作台

- 显示今日发现、评分达标、问候成功和收到简历数量。
- 显示当前运行岗位和任务控制按钮。
- 显示当前 HR 今日已使用、剩余和总计 200 次共享额度。
- 按岗位展示额度消耗明细，但只作为统计，不是岗位独立额度。
- 显示最近筛选、问候和归档动态。

### 2. 岗位管理

- 展示全部岗位及运行、暂停状态。
- 展示岗位名称、候选人数、评分阈值和最近运行时间。
- 提供搜索、状态筛选、新建岗位入口。
- 点击岗位打开详情面板，展示 JD、硬性条件、AI 评分阈值、问候语和任务状态。
- 不出现岗位独立招呼额度设置。

### 3. 候选人

- 支持按岗位、处理状态和 AI 分数筛选。
- 列表展示姓名、目标岗位、AI 分数、判断摘要、问候状态和简历状态。
- 点击候选人打开详情面板，展示经历摘要、匹配证据、风险提示和操作记录。
- 支持演示“查看简历”和“加入待沟通”等操作。

### 4. 简历库

- 岗位选择器是页面第一层、最醒目的筛选入口。
- 未选岗位时提示用户先选择岗位，不直接混合展示全部简历。
- 选择岗位后，仅展示归属于该岗位的简历。
- 在岗位结果内继续按姓名、AI 评分、标签和简历状态筛选。
- 显示该岗位的人才数量、已交换数量和新增简历数量。
- 同一候选人匹配多个岗位时，可在多个岗位结果中出现，并标示“还匹配其他岗位”。

### 5. 系统设置

- 展示当前 HR 账号和角色。
- 展示已连接的 BOSS 账号和 Agent 设备。
- 展示每日 200 次共享额度规则及自动刷新时间。
- 展示发送间隔、登录失效、连续异常和额度耗尽时的自动暂停规则。
- 原型中的开关只演示视觉状态，不保存真实配置。

## 导航与交互

- 左侧导航可切换五个页面，当前页面使用深靛蓝胶囊高亮。
- 岗位卡片、候选人行和简历卡片可点击打开右侧详情面板。
- 搜索框、下拉筛选和状态开关提供前端演示反馈。
- 页面切换后保留统一顶部品牌、Agent 在线状态和当前 HR 头像。
- 桌面端完整展示侧栏；窄屏改用顶部横向页面切换入口。

## 视觉语言

- 主色：深靛蓝 `#090E80`。
- 辅色：蓝紫、青色柔和渐变。
- 背景：白色与淡蓝紫半透明层次。
- 标题：`Marcellus` 衬线字体；界面文字使用 `Urbanist` 与 `Noto Sans SC`。
- 形状：大圆角面板、胶囊按钮、圆形虚线轨道。
- 动效：页面淡入、轻微悬浮、进度条和横向文字流；避免影响阅读的复杂动画。

## 验收标准

1. 五个导航入口都能点击并切换到对应页面。
2. 五个页面视觉风格一致，品牌均显示为 `LEION HR`。
3. 工作台明确显示“每位 HR 每日 200 次，全岗位共享”。
4. 岗位管理中不提供岗位独立额度设置。
5. 简历库必须先选择岗位，且切换岗位后简历与统计同步变化。
6. 候选人、岗位和简历详情均可通过侧边面板查看。
7. 原型在桌面和手机宽度下均可浏览。
8. 所有数据均为演示数据，并有清晰的状态反馈。
